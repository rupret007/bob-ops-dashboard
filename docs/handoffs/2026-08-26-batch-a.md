## Testing and CI interpretation

Use four separate evidence classes. Never collapse them into one green/red label.

1. **Hosted green:** the current default-branch SHA has a completed, relevant product workflow with a successful conclusion.
2. **Locally green:** the strongest available local tests/build passed, but hosted execution is absent, did not start, or has a confirmed external block. Record the command and commit in the private task that ran it.
3. **External failure:** hosted execution did not begin, or an evidenced billing, runner, helper, credential, or service gate prevented validation. A zero-step result alone does not identify the cause. This is neither code green nor code red.
4. **Owner-only validation:** physical feel, device signing, sending, uploading, live-provider use, and production behavior cannot be proved by offline tests.

## Exact approval rules

- A merge approval applies only to the exact head shown to the owner. Any new commit invalidates that approval.
- For a stack, merge the parent normally, verify the merge commit, retarget the child to the default branch without changing its head, revalidate, then request or apply the exact approval that covers that head.
- Never use administrator bypass and never delete branches as part of this portfolio loop.
- A green check authorizes nothing outside the repository. Deployment, publishing, spending, billing changes, credentials/settings, live data, messaging, signing, and physical work each need their own explicit approval.
- Private content and private repository metadata stay out of this public handoff even when an authenticated agent can see them.

## Durable lessons

- Revalidation beats remembered state. PR numbers, draft flags, heads, bases, checks, and mergeability can change independently.
- Generated dashboard churn must never be mixed into source feature reviews.
- A hosted red can be external to the code; read the job annotation before changing code and name a cause only when the evidence supports it.
- A zero-step hosted failure proves only that no hosted execution occurred. Its cause remains unconfirmed, it is not a code failure, and it must never trigger an automatic rerun.
- A local pass does not prove production, device, physical, or live-provider behavior.
- Default-branch changes can publish Pages automatically. Surface that live impact before an exact-head merge decision, even for documentation-only work.
- A public dashboard must fail closed: inaccessible private state stays high-level, stale probes become Unknown, and missing current-tip CI becomes pending rather than inherited green.
- Keep working implementations. Make narrow fixes backed by a regression instead of rewriting stable code.
